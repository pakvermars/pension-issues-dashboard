# 퇴직연금 주요 이슈 데일리 대시보드

매일 퇴직연금·연금 주요 이슈를 최대 20건까지 수집·요약해 보여주는 화면.

## 보는 방법

- **PC** — 이 폴더의 `index.html` 더블클릭
- **웹·휴대폰** — https://pakvermars.github.io/pension-issues-dashboard/
  (공개 주소. 로그인 없이 어디서나 열린다. 같은 주소가 계속 갱신된다.)

## 화면

일간 / 주간 / 월간 / 연간 4개 탭. 각 탭에 최대 20건.

- 상단 기간 축에서 탭을 고른다. 오른쪽으로 갈수록 보는 기간이 넓어진다.
- 분야 5종으로 걸러 볼 수 있다.
  - `제도·규제` — 법 개정, 감독당국 가이드라인, 정부 제도 개편 방향
  - `업계·경쟁사` — 사업자의 점유율·순위, 신상품 출시, 수수료 경쟁, 경영진 인터뷰
  - `운용·상품` — 시장 전체의 자금 흐름과 수익률, 상품군 동향, 자산배분 제언
  - `법인·자금운용` — 개별 기업의 적립금 운용, IPS, OCIO·위탁운용, 사외적립, 기금형 운용주체
  - `가입자·사회` — 개인 수령·인출, 고령화·노후설계, 국민연금·기초연금
- **일간은 그날 게재된 기사만** 담고, 하루 다섯 번 갱신되며 쌓인다. 20건이 안 되면
  안 되는 대로 둔다. 상한은 `rollup.py`의 `TOP_N` 하나로 정해진다.
- **탭마다 고르는 기준이 다르다.** 안 그러면 셋이 같은 목록이 된다.
  - `주간` — 최고 중요도 → 기사 수 → 최신순
  - `월간`·`연간` — 며칠에 걸쳐 다뤄졌나(지속성)를 먼저 본다. 오래 간 이슈가 위로 온다.
  - `월간`은 한 주가 12건, `연간`은 한 달이 8건을 넘지 못한다. 사건이 터진 주·달이
    목록을 독차지하는 걸 막는다.
- `원문 보기`로 기사 전문으로 이동한다.
- 주간 이상 탭에서는 같은 사건을 다룬 기사가 `관련 기사 N건`으로 접혀 있다.
- 게재일은 `오늘`·`어제`·`3일 전`처럼 기준일 대비로 표시된다.

## 자동 갱신

Windows 작업 스케줄러에 작업 **두 개**가 등록돼 있다.

**`퇴직연금 주요 이슈 게이트`** — 07:00부터 20:00까지 **15분마다** `run_gate.ps1`.
새 기사가 나오면 20분 안에 웹에 반영하는 주 경로다.

**`퇴직연금 주요 이슈 데일리`** — 07:37부터 3시간마다 19:37까지 **다섯 번** `run_daily.ps1`.
게이트가 통째로 죽어도 하루 다섯 번은 돌게 하는 안전망이다.

### 게이트가 하는 일

수집 한 번은 `claude -p` 세션을 통째로 쓴다(2~3분). 15분마다 그걸 돌리면 대부분은
"새 기사 없음"으로 끝나면서 비용만 나간다. 그래서 싼 단계와 비싼 단계를 갈랐다.

1. `check_new.js`가 네이버에서 **오늘 기사 URL 목록만** 긁는다. Claude 없이 Node로
   단독 실행되고 **7초**면 끝난다. 검색어는 넓은 것 둘(`퇴직연금`, `연금개혁`)만 쓴다 —
   새 기사가 있는지만 알면 되고, 실제 수집은 `naver_news.js`가 12개를 다 돈다.
   15분마다 12개를 긁으면 네이버 요청이 하루 600회를 넘어 차단 위험이 있다.
2. `gate.py`가 그 URL을 오늘 일간 파일에 이미 담긴 것과 견준다. 새 게 없으면 끝.
   있으면 `run_daily.ps1`을 부른다.

**한 번 제시한 URL은 `data/gate-seen.json`에 기억해 둔다.** 수집이 그 기사를 선별에서
떨어뜨리면 일간 파일에는 안 들어가는데, 기억이 없으면 15분 뒤 같은 URL로 또 수집이
돌아 영영 반복된다.

**오늘 기사도 이전 기사도 0건이면 셀렉터가 깨진 것으로 보고 수집을 돌린다.** 조용히
넘기면 네이버가 클래스명을 바꾼 걸 며칠 뒤에나 알게 된다.

게이트 실행 기록은 `logs/gate-YYYY-MM.log`에 따로 쌓인다. 하루 50번 넘게 도는 로그를
일간 로그에 섞으면 수집 기록이 묻힌다.

두 작업이 동시에 터지는 건 `logs/.run.lock`이 막는다. 앞 실행이 15분 넘게 잡고 있으면
죽은 것으로 보고 무시한다.

게시는 `publish.ps1`이 맡는다. `git push` 하면 GitHub Pages가 1분 안에 반영한다.
Claude가 아니라 스크립트가 하는 이유는 `claude -p` 헤드리스 세션에
`Artifact` 도구가 주입되지 않기 때문이다 — 이걸 몰라서 이틀간 웹만 멈춰 있었다.

일간은 그날 나온 기사를 실행할 때마다 쌓아간다. 아침에는 몇 건이던 것이
저녁에는 그날치가 다 차 있다. 이미 담긴 기사는 다시 담지 않는다.

- 실행 시각에 PC가 꺼져 있었으면, 다음에 켤 때 이어서 실행된다.
- 실행 기록은 `logs/daily-YYYY-MM.log`에 쌓인다.
- 작업을 끄거나 시간을 바꾸려면 `작업 스케줄러`(taskschd.msc)에서 같은 이름의 작업을 연다.

클라우드 예약 에이전트를 쓰지 않은 이유: 클라우드 세션은 이 PC의 `data/` 폴더에
접근할 수 없어 과거 데이터 누적과 기간별 집계가 불가능하다.

작업 스케줄러는 `pwsh`(PowerShell 7)를 부른다. `powershell.exe`(5.1)는 BOM 없는
UTF-8 스크립트를 CP949로 읽어 한글을 깨뜨린다.

## 직접 갱신하기

Claude Code를 열고 `오늘 이슈 갱신해줘`라고 하면 된다.
수집·요약 절차는 `daily_update.md`에 있다.

명령을 직접 실행하려면:

```bash
python -X utf8 gate.py      # 새 기사가 있는지만 확인 (7초)
python -X utf8 rollup.py    # 일간 파일들 → 주간/월간/연간 재집계
python -X utf8 build.py     # 데이터 → index.html, artifact.html
```

## 구조

| 파일 | 역할 |
|---|---|
| `periods.py` | 일간/주간/월간/연간 기간 키와 범위 계산 |
| `store.py` | 기간 파일(JSON) 검증과 입출력 |
| `dedupe.py` | 중복·후속 기사 묶기 |
| `rollup.py` | 일간 파일 → 기간별 TOP 20 |
| `build.py` | 기간 파일 → `index.html`(로컬용) + `artifact.html`(웹 게시용) |
| `template.html` | 화면 뼈대. 데이터가 인라인으로 주입된다 |
| `naver_news.js` | 네이버 뉴스에서 기사 목록을 긁는 Playwright 스크립트. 검색어는 여기 `QUERIES`에 있다 |
| `check_new.js` | 오늘 기사 URL만 긁는 게이트용 스크래퍼. Node 단독 실행 |
| `gate.py` | 새 기사가 있는지 판단한다. 없으면 수집을 부르지 않는다 |
| `run_gate.ps1` | 15분마다 도는 진입점. 새 기사가 있을 때만 `run_daily.ps1`을 부른다 |
| `run_daily.ps1` | 수집 진입점. 게이트와 3시간 안전망이 부른다 |
| `publish.ps1` | 빌드 결과를 GitHub Pages에 올린다 (git add/commit/push) |
| `daily_update.md` | 매일 수행하는 수집 절차 |
| `data/` | 날짜별 원본 데이터. 지우면 과거 이슈가 사라진다 |
| `data/gate-seen.json` | 게이트가 이미 제시한 URL. 같은 기사로 수집이 반복되는 걸 막는다 |
| `data/merges.json` | 같은 사건/다른 사건을 사람이 바로잡는 곳. 기간 파일을 직접 고치면 3시간 뒤 덮어써진다 |

`index.html`과 `artifact.html`은 `build.py`가 만드는 결과물이라 직접 고치지 않는다.
화면을 바꾸려면 `template.html`을 고친다.
