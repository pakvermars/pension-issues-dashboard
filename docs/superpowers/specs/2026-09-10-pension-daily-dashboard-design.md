# 퇴직연금 주요 이슈 데일리 대시보드 — 설계

작성일: 2026-09-10

## 1. 목적

퇴직연금·연금 관련 주요 이슈와 뉴스를 매일 자동으로 수집·요약해, 하나의 웹 화면에서
**일간 / 주간 / 월간 / 연간** 관점으로 볼 수 있게 한다. 각 항목은 요약과 함께 원문 링크를
제공해 필요 시 바로 기사 전문으로 이동할 수 있어야 한다.

## 2. 사용자와 사용 맥락

- 사용자: 퇴직연금 업무 담당자 1인
- 사용 시점: 매일 아침 출근 전후, 그날의 이슈를 훑는 용도
- 보는 방법 두 가지를 모두 지원한다
  - 로컬: 바탕화면 폴더의 `index.html` 더블클릭 → 브라우저에서 열람
  - 웹: 비공개 Artifact URL → 휴대폰 열람 및 필요 시 팀 공유

## 3. 범위

### 포함

- 당일 기준 퇴직연금·연금 주요 이슈 10건 수집, 요약, 원문 링크
- 주간·월간·연간 기간별 TOP 10 재선별
- 4개 탭(일간/주간/월간/연간)으로 구성된 단일 화면
- 매일 자동 갱신

### 제외 (YAGNI)

- 사용자 로그인, 다중 사용자
- 검색 기능, 북마크, 코멘트
- 서버·데이터베이스 (파일 기반으로 충분)
- 기사 전문 저장 (링크만 제공, 저작권 고려)

## 4. 아키텍처

데이터와 화면을 분리한다. 뉴스는 날짜별 JSON으로 누적되고, 화면은 그 JSON을 읽어
생성된다. 과거 데이터가 남아야 기간별 재선별이 가능하고, 화면 디자인 변경이
데이터에 영향을 주지 않는다.

```
퇴직연금 주요 이슈/
├─ index.html                  # 보는 화면. 데이터 내장(인라인), 단독 실행 가능
├─ data/
│  ├─ daily/YYYY-MM-DD.json    # 원본 누적 (매일 1개)
│  ├─ weekly/YYYY-Www.json     # 재선별 결과
│  ├─ monthly/YYYY-MM.json
│  └─ yearly/YYYY.json
├─ build.py                    # data/*.json → index.html 생성
└─ docs/superpowers/specs/     # 설계 문서
```

`index.html`은 데이터를 파일 안에 인라인으로 담는다. `file://`로 열 때 외부 JSON을
`fetch`하면 브라우저 보안 정책에 막히므로, 별도 서버 없이 더블클릭만으로 열리게 하려면
인라인이 필수다.

## 5. 데이터 모델

### 기사 1건

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | 중복 판별용 키. URL 정규화 후 해시 |
| `title` | string | 기사 제목 |
| `summary` | string | 3~4문장 요약 |
| `category` | enum | `제도·규제` \| `업계·경쟁사` \| `가입자·사회` |
| `importance` | int 1–5 | 선별 근거로 쓰이는 중요도 |
| `source` | string | 언론사명 |
| `published` | date | 게재일 (YYYY-MM-DD) |
| `url` | string | 원문 링크 |
| `related` | array | (기간별 파일 전용) 묶인 후속·중복 기사의 `{title, source, url}` 목록 |

### 기간 파일

```json
{
  "period": "daily",
  "key": "2026-09-10",
  "label": "2026-09-10 (목)",
  "generated_at": "2026-09-10T07:40:00+09:00",
  "item_count": 10,
  "shortfall_note": null,
  "items": [ /* 기사 객체 배열 */ ]
}
```

`shortfall_note`는 10건을 채우지 못한 날에만 사유 문자열이 들어간다.

## 6. 일일 파이프라인

매일 **오전 7시 40분**(로컬 시간)에 실행한다.

1. **수집** — 다중 쿼리 웹 검색: `퇴직연금`, `IRP`, `확정기여형 DC`, `확정급여형 DB`,
   `디폴트옵션`, `퇴직연금 적립금`, `퇴직연금 수익률`, `연금개혁`, `TDF`, `기금형 퇴직연금`
2. **중복 제거** — URL 정규화 및 제목 유사도로 동일 사건 기사를 하나로 묶는다
3. **선별** — 세 관점(제도·규제 / 업계·경쟁사 / 가입자·사회)으로 중요도를 매겨 TOP 10 선정.
   한 카테고리가 전부를 차지하지 않도록 카테고리별 최소 1건을 보장한다
4. **요약** — 각 건 3~4문장. 사실 중심으로 쓰고 기사에 없는 내용을 덧붙이지 않는다
5. **저장** — `data/daily/YYYY-MM-DD.json`
6. **기간별 재선별** — 해당 주/월/연도에 속한 daily 파일을 전부 읽어, 같은 사건의 속보·후속
   기사를 하나로 묶고(`related`에 누적) 다시 TOP 10을 뽑아 각 기간 JSON을 갱신
7. **빌드 및 게시** — `build.py`로 `index.html` 재생성, 동일 Artifact URL로 재게시

### 주간 경계

주는 월요일 시작, 일요일 종료(ISO 주). 주간 키는 `YYYY-Www` 형식.

## 7. 화면

- **헤더** — 제목, `2026-09-10 (목) 기준`, 마지막 갱신 시각
- **탭 4개** — 일간 / 주간 / 월간 / 연간. 기본 선택은 일간
- **카드 목록** — 탭당 최대 10장
  - 순번, 카테고리 배지, 제목
  - 요약 3~4문장
  - 출처 · 게재일
  - `원문 보기` — 새 탭으로 열림
  - 주간 이상 탭에서 묶인 기사가 있으면 `관련 기사 N건` 접이식 링크 목록
- **카테고리 필터** — 배지 클릭으로 해당 카테고리만 표시
- **테마** — 라이트/다크 모두 대응
- **건수 부족 표시** — `shortfall_note`가 있으면 목록 상단에 안내 문구 노출

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| 당일 기사가 10건 미만 | 억지로 채우지 않고 있는 만큼만 표시, `shortfall_note`에 사유 기록 |
| 검색이 아예 실패 | 기존 `index.html`을 그대로 두고 해당 날짜 파일을 만들지 않는다. 화면은 마지막 성공 데이터를 계속 보여준다 |
| 유료·로그인 필요 기사 | 링크는 그대로 제공하되 출처 옆에 `유료` 표시 |
| 특정 날짜 파일 누락 | 기간별 재선별은 존재하는 파일만으로 수행 |

## 9. 검증

- `build.py`는 샘플 JSON을 넣었을 때 유효한 HTML을 만들어야 한다
- 기간 경계 계산(주/월/연 소속 판정)은 연말·연초를 포함한 경계값으로 확인한다
- 생성된 `index.html`을 `file://`로 열어 탭 전환, 필터, 링크가 동작하는지 확인한다
- 데이터가 0건인 경우와 10건 미만인 경우의 화면을 확인한다

## 10. 자동 스케줄 실행 방식 (해결됨, 2026-09-10)

구현 중 확인한 결과 **클라우드 예약 에이전트는 로컬 폴더에 접근할 수 없다.** 클라우드
세션은 자체 git 체크아웃 위에서 돌기 때문에 이 PC의 `data/`를 읽지 못하고, 따라서 과거
데이터 누적과 기간별 집계가 불가능하다. 이 프로젝트는 git 원격 저장소도 없다.

대신 **Windows 작업 스케줄러 + 로컬 `claude` CLI 헤드리스 실행**을 택했다.

- 작업 이름: `퇴직연금 주요 이슈 데일리`, 매일 07:40 (로컬 시간)
- 실행 대상: `run_daily.ps1` → `claude -p "daily_update.md 절차를 수행하라"`
- 로컬 파일과 웹 링크가 한 번에 갱신되고, GitHub 계정이 필요 없다
- `-StartWhenAvailable` 설정으로 그 시각에 PC가 꺼져 있었으면 다음 부팅 후 실행된다
- 제약: PC가 켜져 있고 사용자가 로그온한 상태여야 한다

검토했으나 택하지 않은 대안: GitHub 비공개 저장소를 만들어 클라우드 에이전트가 매일
clone·push 하는 방식. PC 전원과 무관하게 돌지만 계정·저장소 설정이 추가로 필요하고,
로컬 파일은 사용자가 직접 pull 해야 최신이 된다.
